# scenelive

Названия предметов и направления на них **во время съёмки** на телефон, без датчика глубины и без Depth Anything.
Этот каталог содержит ядро и **симулятор на записанном видео**: видео проигрывается как живой поток, а время каждого этапа измеряется.
Сервер и веб-клиент позже подключатся к тем же классам (`FastPath`, `build_map`, `ObjectList`).

## Идея: два цикла

```
телефон: кадр -> сжатие JPEG -> сеть ->  БЫСТРЫЙ ЦИКЛ (каждый кадр, цель: секунда)
                                         preprocess -> compass -> detect -> track -> name -> locate -> list
                                          |  кадры и треки
                                          v
                                         ЦИКЛ КАРТЫ (раз в 5-10 с, фоном)
                                         склейка треков в предметы, голосование имён, дистанции
         <- сеть <- СПИСОК: имя, направление (по часам), расстояние ступенью, статус
                    provisional (только что найден) -> confirmed -> remembered (вне кадра)
```

- **Название**: детектор (YOLO-World: любые слова, в том числе столбы, стены, двери; или YOLO с классами COCO) + голосование по кадрам трека.
- **Направление без глубины**: `азимут = atan((u - cx) / f)` от оси камеры, плюс курс камеры (компас). Курс берётся из лога телефона
  (`--compass heading.csv`) или оценивается по самому видео (`--compass visual`, оптический поток фона).
- **Расстояние без глубины**: `d = f * H_типовой / h_пикселей / cos(азимут)` для предметов с известным размером (человек, машина, дверь, ...);
  для остальных `?`. С перемещением камеры (ARKit) карта пересекает лучи и даёт настоящее расстояние (`rays.py`).
- **Ступени**: 1, 2, 5, 10, 15 м (ближайшая по логарифму), диапазон вида `2-5 m` при большой неопределённости.

## Веб-версия: страница на телефоне и сервер

```
ТЕЛЕФОН (страница в браузере)                         СЕРВЕР (ваш ноутбук, тяжёлые файлы и расчёты здесь)
 камера (по возможности 0,5x)  кадр 640 px, JPEG ──►   разворот JPEG -> компас -> детектор -> трекер -> имя -> положение
 датчик направления (гироскоп/компас) ────────────►   цикл карты раз в 6 с (склейка, подтверждение, "в памяти")
 ◄── список, рамки, времена этапов ──────────────────   живой список: предварительно -> подтверждён -> в памяти
 чат: вопрос ─────────────────────────────────────►   помощник (Claude или офлайн) вызывает инструменты по списку
 ◄── ответ ──────────────────────────────────────────
```

Основа та же, что в симуляторе (`FastPath`, `build_map`, `ObjectList`): страница шлёт 3 кадра в секунду, сервер называет предметы и
считает направления сразу, раз в несколько секунд обновляет карту. Страница лёгкая: один HTML, один скрипт, без библиотек;
сервер написан на стандартной библиотеке Python (HTTP, WebSocket, TLS), поэтому ставить FastAPI или uvicorn не нужно.

### Запуск

1. Один раз: `windows\setup_server.bat` (пакеты `cryptography` для https и `anthropic` для Claude) и, если ещё не делали, `windows\setup_models.bat` (детекторы).
2. Для чата с Claude (необязательно): `setx ANTHROPIC_API_KEY ваш_ключ`, затем откройте **новое** окно. Ключ лежит только на сервере, на телефон не попадает. Без ключа чат работает офлайн: отвечает по ключевым словам (`что вокруг`, `где машина`, `что слева`, `что ближайшее`).
3. `windows\serve.bat`. Первый запуск скачает веса детектора (несколько минут). Сервер напечатает адреса, например `https://192.168.1.5:8443/?token=...`.
4. Телефон в той же сети Wi-Fi: откройте адрес с токеном. Сертификат самоподписанный: браузер предупредит один раз, выберите «Дополнительно» и «Продолжить». Разрешите камеру и датчики движения.
5. Выберите «Сверхширокая 0,5×» и нажмите «Начать». Брандмауэр Windows при первом запуске спросит про доступ: разрешите для частной сети.

Проверка без телефона: `windows\serve.bat` в одном окне, а в другом `windows\client_sim.bat D:\scenelive_videos\street.mp4 --url "https://localhost:8443/?token=XXXX" --chat "Что вокруг?"`: видео уходит на сервер по настоящему WebSocket, печатаются круговые задержки и ответ помощника.

### Камера 0,5×

Браузер не даёт выбрать объектив напрямую. Страница делает так: на iPhone ищет камеру с «Ultra Wide» в названии (виртуальные «Dual/Triple» не берёт); на Android пробует приблизить `zoom` до 0,5, если браузер его показывает; если не вышло, берёт основную камеру и пишет об этом. **Это важно для расстояний:** они пропорциональны фокусному расстоянию, и при неверном угле обзора все расстояния ошибаются (до 1,7 раза для 0,5× при 69°). Угол можно задать вручную полем «Угол обзора».

### Курс камеры

На телефоне берётся направление из датчиков (`DeviceOrientation`): страница считает, куда смотрит задняя камера, и шлёт это вместе с кадром. Если датчиков нет или доступ не дан, сервер оценивает курс по видео (хуже при ходьбе вперёд).

### Что находит система (словарь)

В каталоге 119 классов в 12 категориях: люди, транспорт, животные (собака, лошадь, корова, змея, медведь, волк...), конструкции (стена, здание, забор, дверь, лестница, бордюр...), в помещении (штора, диван...), растения и камни (дерево, куст, ветка, камень...), уличные объекты (столб, светофор, знак...), препятствия (дорожный конус, строительные леса, кабель...), опасности (яма, выбоина, лужа, лёд, грязь, открытый люк, разбитое стекло, шприц, огонь, оголённый провод...), оружие и острые предметы (нож, оружие, топор, бензопила, бита), мусор (мусор, пакет, бутылка, куча мусора, обломки...) и покрытие (дорога, асфальт, плитка, гравий, трава...). Каждый класс имеет русское название и степень: **опасно** (предупреждать сразу), **осторожно** (упомянуть, если близко) или **информация**.

`windows\vocab.bat` печатает таблицу, `windows\vocab.bat --out my_vocab.txt` пишет файл со словами для правки (удалите лишнее, добавьте своё), `windows\serve.bat --vocab my_vocab.txt` берёт его. `--vocab core` возвращает прежние 28 слов, `--vocab extended` (по умолчанию) весь каталог. Детектор `yolo` (COCO) тоже находит нож, ножницы, биту, лошадь, корову, медведя, бутылку.

Оговорки: детектор с открытым словарём лучше находит людей и машины, чем «дорогу», «стену» или «мусор»; для оружия и опасных предметов он ошибается в обе стороны (пропускает и принимает за них другое). Зависимость скорости от размера словаря не измерена: сравните `windows\bench.bat видео --vocab core` и `--vocab extended`.

### Покрытие под ногами: дорога, асфальт, плохая дорога

Дорога это область, а не предмет с рамкой, и детектор рамок её видит плохо. Поэтому нижняя часть кадра делится на три зоны (слева, впереди, справа), раз в секунду каждая зона классифицируется (CLIP по описаниям вида «a photo of asphalt on the ground»), результат сглаживается по трём последним взглядам, чтобы один странный кадр не объявлял яму. Двадцать типов: асфальт, бетон, плитка, тактильная плитка, пешеходный переход, пол, ковёр, мокрый асфальт, брусчатка, гравий, грунт, песок, трава, потрескавшийся асфальт, яма, лужа, грязь, снег, лёд, лестница. У каждого есть качество: хорошее, среднее или плохое. «Плохая дорога» это яма, лужа, грязь, снег, лёд, лестница или потрескавшийся асфальт при уверенности не ниже 0,4.

Включение: `windows\serve.bat --ground clip`. В моей среде нет torch, поэтому на настоящем CLIP это **не запускалось**: точность и время неизвестны. Измерьте на вашем видео: `windows\replay.bat видео.mp4 --ground clip` добавит в отчёт строку этапа `ground` (она выполняется раз в секунду). На странице под видео показываются три плашки (слева, впереди, справа) с типом и качеством покрытия.

### Предупреждения

Страница говорит и показывает баннер сама, без вопроса:

- **опасный предмет** (нож, оружие, огонь, открытый люк, хищник, разбитое стекло...): сразу, после трёх наблюдений и при уверенности не ниже 0,35, например «Осторожно! Опасность: возможно, нож, справа-спереди, около 3 метров»;
- **машина, крупное животное, препятствие** ближе 6 м и впереди (в пределах 60° от курса); яма, лёд, лужа прямо по курсу;
- **плохое покрытие** прямо по курсу.

Чтобы не утомлять: одно и то же не повторяется 15 секунд, не чаще раза в 2,5 секунды, не больше одного за раз; опасное идёт первым. `--no-alerts` выключает, `--alert-range 8` меняет дальность.

### Помощник и голос

Помощник отвечает по списку и покрытию (инструменты `scene_summary`, `list_objects`, `where_is`, `objects_in_direction`, `nearest_objects`, `ground_info`, `hazards`). Вопросы: «что вокруг?», «где машина?», «что слева?», «какая дорога?», «что опасного?», «есть ли животные?», «где мусор?», «видишь штору?». На оружие и опасное он отвечает осторожно: «Возможно...», а если ничего не видно, говорит «не вижу, но камера могла не заметить, это только подсказка» и никогда не говорит, что безопасно. Ответы короткие и без символов, чтобы их было удобно читать вслух.

**Голос работает в браузере телефона, на сервере ничего лишнего:** кнопка «Говорить» (распознавание речи, Chrome и Safari) и озвучивание ответов и предупреждений (флажок «озвучивать»; опасность прерывает речь). Ограничения: Chrome отправляет звук на серверы Google; на iPhone нужна включённая диктовка; русский голос зависит от системы; пробуждения голосом нет, кнопку нужно нажимать. Подробности и вариант с распознаванием речи на самом сервере (Whisper и Piper): `docs\VOICE.md`.

### Память: предметы не теряются

Раньше предмет, виденный несколько секунд, мог на время пропасть из списка (до 6 секунд), и помощник говорил «не вижу». Теперь:
- Карта строится **раз в секунду** и **в тот же момент, когда предмет выходит из «живого» списка** (она занимает миллисекунды), так что провала нет.
- Трек держится дольше (10 пропущенных кадров вместо 6). Слабая находка (уверенность от 0,15 до 0,30) может **продолжить** трек, но не начать новый: так мерцание детектора не рвёт трек. Ключи: `--conf` (порог начала, 0,30) и `--floor-conf` (нижний предел детектора, 0,15).
- Предмет вне кадра получает статус «в памяти» сразу, через секунду после ухода, и помощник говорит, как давно его видел.
- Один уверенный взгляд (уверенность от 0,55) запоминается, даже если находка была одна: мельком увиденную машину забывать нельзя.
- Классы, которые на ваших записях срабатывали ложно (рекламный щит, коляска, банка, киоск, почтовый ящик, инвалидная коляска, тележка), требуют 4 находки подряд.
- Радар объединяет одинаковые предметы в одном секторе в одну отметку («человек ×3») и не подписывает «запомненные».

### Для людей, которые не видят дорогу

Подробно: `docs\SAFETY.md`. Коротко: это подсказка, а не замена трости или сопровождающего; помощник не говорит «безопасно», при потере связи страница сама предупреждает голосом, режим «куда идти» (`--seg segformer`) сделан, но на реальных маршрутах не проверен.

### Свободное пространство и «куда идти»

Стена, пол и проход это области, а не предметы с рамкой, поэтому их находит сегментация (модель SegFormer-B0, обучена на 150 классах).

```bat
windows\setup_seg.bat                                   :: один раз: пакет transformers (модель скачается сама, около 15 МБ)
windows\serve.bat --seg segformer                        :: с подсказками «куда идти»
windows\serve.bat --seg segformer --seg-size 448         :: быстрее: меньше пикселей на входе модели (проверьте картинки через bench_seg --size 448)
windows\serve.bat --seg segformer --camera-height 1.3    :: если телефон держите ниже или выше 1,4 м
```

**Как работает.** Раз в секунду, в отдельном потоке (чтобы тяжёлая модель не тормозила кадры), кадр делится на группы: пол и тротуар, **проезжая часть** (отдельно от тротуара!), неровная земля, стена, дверь, лестница, стекло, движущееся, препятствие. Дальше по каждому столбцу картинки идём вверх от ног, пока идёт «можно идти»; там, где это кончилось, препятствие (или край тротуара) стоит на земле. Строка картинки превращается в расстояние по высоте телефона и наклону камеры (наклон приходит с датчиков телефона). Кадр делится на пять секторов, для каждого считается, как далеко свободно и что это останавливает. **Называется меньше, чем измерено (80 %):** лучше недооценить свободное место. «Стоп» при менее 1,5 м, «осторожно» при менее 3 м.

**Что получает человек.**
- Вопросы «куда идти?», «можно ли идти?», «где проход?», «где стена?», «веди к двери» (помощник проверяет, свободен ли путь к известному предмету; Claude получает те же инструменты `where_to_go` и `free_space`). Ответ вроде «Прямо свободно около 3 метров, дальше стена. Камера может не заметить стекло, ступеньку вниз или яму.»
- Сам говорит: «Стоп. Впереди стена, меньше метра» и «Внимание! Похоже, вы на проезжей части» (не чаще раза в 15 секунд).
- На странице строка с советом и цветные секторы свободного места на радаре (зелёный далеко, жёлтый близко, красный очень близко).

**Когда говорит «не уверен».** Нет наклона телефона (датчики не разрешены), камера наклонена слишком сильно или вверх, модель сама не уверена, картинка пола старше 3 секунд. Тогда совет один: «Я не вижу путь надёжно. Остановитесь и не полагайтесь на подсказки.»

**Что проверено, а что нет.** Геометрия и логика проверены автотестами на точных картинах (стена ровно в 3 м находится в 3 м; порог «стоп»; дорога против тротуара; не уверен без наклона). Модель на ваших 12 кадрах улицы различает дорогу, тротуар, здания, людей и машины, скорость 343 мс на кадр (2,9 кадра/с, замер без `--seg-size`). **Не проверено:** точность расстояний по рулетке, коридор в помещении, темнота, ступени и стекло, нагрузка на процессор при одновременной работе детектора и сегментации (смотрите время этапов и `seg.mean_ms` на `/api/stats`).

### Безопасность

Адрес в локальной сети защищён токеном (создаётся сам; сокет и `/api/stats` без него не открываются). Кадры нигде не сохраняются. Ответы сервера имеют строгую политику содержимого (CSP), отдаются только известные файлы страницы. Не открывайте сервер в интернет без дополнительной защиты: это личный инструмент.

### Что проверено, а что нет

Проверено автотестами и независимым клиентом (встроенный WebSocket Node.js): рукопожатие и кадры, протокол и ошибки, ограничения, отбрасывание старых кадров, токен, https, сквозная работа с симулятором телефона, формулы курса по датчикам и выбор камеры по названиям (на примерах iOS и Android). **Не проверялось в настоящем браузере и на телефоне:** сама страница (камера, датчики, отрисовка), поведение Safari и Chrome с самоподписанным сертификатом, работа настоящих детекторов через сервер. Первый запуск на телефоне может выявить мелочи, пришлите текст из строки состояния и заметок страницы.

Протокол обмена: `docs\PROTOCOL.md`.

windows\setup.bat            :: ядро: numpy, opencv (хватает для демо и тестов)

## Запуск на вашем видео

Положите видео в папку с латинским путём (например `D:\scenelive_videos\street.mp4`).

```bat
windows\bench.bat D:\scenelive_videos\street.mp4 --detector world --imgsz 320,480,640
windows\replay.bat D:\scenelive_videos\street.mp4 --detector world --fps 3 --out-video
windows\replay.bat D:\scenelive_videos\street.mp4 --detector yolo --imgsz 480 --fps 4
windows\replay.bat D:\scenelive_videos\street.mp4 --camera ultrawide --compass heading.csv
```

Сначала `bench`: он показывает, сколько миллисекунд уходит на детектор при разных размерах входа (это самый медленный этап).
Потом `replay`: полный прогон со сводкой. Результаты лежат в `runs\<время>\`: `report.txt`, `stages.csv`, `frames.csv`,
`events.csv`, `first_names.csv`, `report.json`, `overlay.mp4` (с ключом `--out-video`).

По сводке нельзя сказать, какие названия верные. Для этого нужна разметка нескольких моментов видео (10-15 кадров достаточно).
Все команды выполняются из папки проекта (`D:\scenelive`).

1. **Прогон новой версией** (создаёт `tracks.csv`): `windows\replay.bat D:\scenelive_videos\street.mp4 --detector world`.
   Папка прогона печатается в конце: `runs\20261105_103015`. Список папок: `dir runs`.
2. **Кадры для разметки:** `windows\snapshots.bat D:\scenelive_videos\street.mp4 --every 4` создаёт `runs\snapshots_<время>\t_0004.0.jpg`,
   `t_0008.0.jpg` и т.д. Число в имени это секунда видео.
3. **Заготовка файла:** `windows\labels_template.bat runs\20261105_103015 --every 4` создаёт `labels.csv` в папке проекта
   (существующий файл не перезаписывается). Откройте его в Блокноте.
4. **Разметка:** для каждой секунды посмотрите кадр и впишите, что видно, строками `секунда, класс, сколько` (например `4.0, person, 2`).
   Классы по-английски. Впишите все предметы тех классов, которые вас интересуют.
5. **Оценка:** `windows\eval.bat runs\20261105_103015 labels.csv`.

Если файла `labels.csv` нет, а папка прогона старая (нет `tracks.csv`), команды сами объяснят, что сделать.

`eval` печатает таблицу по порогам (TP, FP, FN, precision, recall, F1), оценку по каждому классу и подсказку `--min-conf-publish`.

## Мерцание и подтверждение

Имя показывается, если трек обнаружен не меньше `--publish-hits` раз (по умолчанию 2) или одна находка уже уверена на
`--publish-single-conf` (0,55). Это убирает одно-кадровое мерцание детектора ценой одного кадра задержки для слабых находок.
Статус «подтверждён» требует `--confirm-hits` находок и `--confirm-conf` уверенности. У YOLO-World уверенность обычно ниже, чем у YOLO
(0,3-0,5), поэтому порог подтверждения, возможно, стоит снизить. `tracks.csv` содержит строку на каждый трек в каждом кадре
(имя, уверенность, число находок, рамка, направление, расстояние) для любого постороннего анализа.

## Как читать отчёт

- **STAGE TIMING**: по каждому этапу число вызовов, среднее, медиана, p95, максимум, суммарное время и доля в серверном времени.
  Этапы телефона (`client_resize`, `client_encode`), сервера (`server_decode`, `preprocess`, `compass`, `detect`, `track`, `name`, `locate`, `list`)
  и карты (`map_build`). Строка `the slowest stage` называет главное узкое место.
- **END TO END**: задержка кадра от съёмки до появления результата на телефоне (среднее, p50, p95, максимум), сколько кадров отброшено,
  сколько кадров в секунду сервер выдержит, и вердикт «успевает или нет».
- **FIRST NAMES**: для каждого трека секунда первого обнаружения, секунда, когда имя появилось в списке, задержка и секунда подтверждения.
- **LIST AT THE END**: список, как его увидел бы телефон в конце (имя, статус, «часы», расстояние, уверенность).

## Модель времени

Два вида времени: время видео (когда снят кадр) и время вычислений (измерено на этом компьютере `perf_counter`). Симулятор проигрывает
их как в реальной системе: сеть вверх и вниз (`--uplink-ms`, `--downlink-ms`), **один** серверный обработчик, очередь кадров.

| Ключ | Что делает |
| --- | --- |
| `--fps` | сколько кадров в секунду шлёт телефон (по умолчанию 3) |
| `--compute-scale 3` | «а если сервер втрое медленнее» (`0.1`: в десять раз быстрее) |
| `--client-factor 3` | телефон медленнее ноутбука при сжатии кадра |
| `--no-latest-wins` | не отбрасывать старые кадры, когда сервер не успевает (очередь растёт) |
| `--shared-cpu` | цикл карты занимает тот же процессор и задерживает быстрый цикл |
| `--map-interval` | как часто строится карта (секунды) |
